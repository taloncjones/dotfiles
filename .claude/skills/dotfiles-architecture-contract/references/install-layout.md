# Install layout, symlink targets, and hook catalogue

**Install flow:** `bootstrap.sh` -> `install/install.sh` -> platform-specific scripts

- `install/macos/macos.sh` - Homebrew, Brewfile, VS Code extensions, Xcode CLI
- `install/linux/linux.sh` - apt packages, Linuxbrew
- `install/{macos,linux}/link.sh` - Create symlinks
- `install/macos/defaults.sh` - macOS system preferences
- `install/common/zsh.sh` - Set Homebrew ZSH as default shell

**Symlink targets:**

- `zsh/` -> `~/.zshrc`, `~/.zprofile`, `~/.zshenv` (`.zshenv` sources both account wrappers so Claude routing and Codex's personal-repository Atlassian exclusion work in non-interactive shells; machine-local additions live in `~/.zshenv.local`, migrated there from a pre-existing `~/.zshenv` by `install/common/zshenv-migrate.sh`)
- `git/` -> `~/.gitconfig` (no `[user]` block; identity comes from `includeIf` only — `useConfigOnly` makes git refuse to commit outside `~/Git/personal` and `~/Git/work`)
- `git/personal/.gitconfig-personal` -> `~/.gitconfig-personal` (tracked)
- `git/work/.gitconfig-work.tmpl` seeded to `~/.gitconfig-work` on first install (machine-local; run `identity-setup` to populate employer values)
- `ssh/configs/config` -> `~/.ssh/config` (Includes `~/.ssh/config_local` first, then personal/work sub-configs; no global `ForwardAgent`)
- `ssh/configs/agent.toml` seeded to `~/.config/1Password/ssh/agent.toml` on first install (machine-local)
- `ssh/keys/id_ed25519_personal.pub` -> `~/.ssh/id_ed25519_personal.pub`; work key (`~/.ssh/id_ed25519_work.pub`) is machine-local, written by `identity-setup`. `~/.ssh/id_ed25519_git_fallback` (machine-local, never tracked) is an optional GitHub-only on-disk key listed second in `config_personal` so git-over-SSH keeps working while the 1Password vault is locked (the agent serves no keys when locked); ssh skips it where absent
- `ssh/configs/config_cloudflared.tmpl` seeded to `~/.ssh/config_cloudflared` on first install (machine-local; the real zone is edited there, the template keeps the inert `*.ssh.example.com` placeholder). Included from `ssh/configs/config` after `config_local`. Client side of Cloudflare Access SSH; host-side tunnel, Access app, and sshd are a manual runbook in README "Remote Access", never installer-driven.
- `bin/remote-access-doctor` -> `~/bin/remote-access-doctor` -- read-only checker for the Cloudflare Access SSH client stanza and host role (tested by `bin/remote-access-doctor.test.sh`)
- `bin/zed-claude-agent` -> `~/bin/zed-claude-agent` -- launches the pinned Claude Code ACP adapter for one account (`personal`|`work`), resolving the account through `claude/skills/lib/workflow_context.py` and applying its `launch_env` (so personal launches with `CLAUDE_CONFIG_DIR` unset), with `ANTHROPIC_API_KEY` unset (tested by `bin/zed-claude-agent.test.sh`)
- `bin/herdr-zed-attach` -> `~/bin/herdr-zed-attach` -- run from a Zed Terminal Thread (`agent: new terminal thread`), resolves the herdr agent whose `cwd` or `foreground_cwd` is at or under the current git toplevel from `herdr agent list` and execs `herdr agent attach <pane_id>`; lists candidates on stderr and exits 1 (none) or 2 (several); an explicit pane ID or agent name argument bypasses resolution; no account routing because attaching joins an already-bound pane; the sidebar label does not follow the agent's title and `agent.terminal_init_command` stays unused (tested by `bin/herdr-zed-attach.test.sh`)
- `vscode/` -> VS Code settings/keybindings
- `zed/` -> `~/.config/zed/settings.json` (per-file link, vscode pattern; the link must target the MAIN checkout's `zed/settings.json`, never a worktree copy, because worktrees die at merge -- `update` after merge re-links it). The `agent_servers` block defines three Claude entries: `claude-personal`, `claude-work`, and `claude-acp`, a compat alias for the personal account that stays until every saved Zed space created under that name is migrated (Zed resolves saved spaces by agent name; removing the entry broke every saved space on 2026-09-19). Each entry launches `~/bin/zed-claude-agent <personal|work>` (linked from `bin/`) and unsets `ANTHROPIC_API_KEY` -- Zed's env values are passed literally, so account routing cannot live in this file; the command field IS tilde-expanded, which is why the wrapper does the work. The wrapper resolves the account through `claude/skills/lib/workflow_context.py`, the same provider the `claude()` shell wrapper uses, keyed on the project root Zed passes as the adapter's cwd, and applies the returned `launch_env`; when the resolved account disagrees with the entry's argument it exits 3 with a message instead of launching, which is how a work entry behaves on a machine with no work account. Never reintroduce a hardcoded account-to-directory map: setting `CLAUDE_CONFIG_DIR` selects a separate authentication namespace even when it names the default directory (every explicit value gets its own `Claude Code-credentials-<hash>` Keychain item), so the personal account MUST launch with it unset, as `workflow_context.py`'s own docstring requires. Pinning it to `$HOME/.claude` put every Zed thread in a namespace that had never been logged in, surfacing as `OAuth session expired and could not be refreshed` (2026-09-20). A machine-local `~/.claude/.credentials.json` is not the remedy: a copied token is a static snapshot that cannot rotate, so it expires again -- never commit credentials or put a token in this tracked file. `themes/`, `prompts/`, and the rest of `~/.config/zed/` stay machine-local.
- `claude/` -> `~/.claude/` AND `~/.claude-work/` (`CLAUDE.md` linked from `claude/global-instructions.md`, commands, agents, hooks, skills, rules). The installed `CLAUDE.md` links to `claude/global-instructions.md` because a tracked `CLAUDE.md` under `claude/` is loaded a second time as nested project memory. Two config dirs, one asset source: `~/.claude` is the personal Claude account (default -- desktop app and unwrapped launches), `~/.claude-work` is the work account, selected by the `claude()` wrapper in `zsh/claude-account.zsh` whenever claude is launched under `~/Git/work` (`claude --personal` or a pre-set `CLAUDE_CONFIG_DIR` overrides; `claude-account` shows the routing). A linked worktree of a repo under `~/Git/work` (herdr, EnterWorktree, `.worktrees/`) routes to work too, resolved through the shared canonical repository/account provider; `account_guard.py` uses the same ownership metadata while permitting personal quota. Herd dispatch explicitly binds the selected account and runtime environment in the server-spawned pane, including unsetting the default personal Claude directory. Each dir keeps its own machine-local `settings.json` (seeded from the template; both drift-checked by `claude/hooks/claude-hooks.test.sh`) and its own plugin installs, though no plugin installs any more since the retired Superpowers install path (like the retired ECC's) is gone; `bootstrap` and every `update` run `install/common/claude-plugins.sh`, which now only keeps retired plugin copies disabled. `claude/agents/` is whitelist-tracked (committed `claude/agents/.gitignore`: everything ignored except named personas) because installers (historically the retired ECC full install) wrote vendored agent files into it through the symlink; `claude/agents/director.md` is the tracked `claude --agent director` entrypoint for the standing per-repo herdr director (the role's user-facing name; the `tier: "launcher"` schema value is unchanged).
- `claude/rules/` -> `~/.claude*/rules`. Claude Code natively auto-loads every `.md` under `~/.claude/rules/` at launch (verified live in a cloud session, 2026-07-02): files with a `paths:` frontmatter load only when matching files are in context, files without one load every session. Only our own always-on rules under `claude/rules/personal/` are tracked (e.g. `claude-prompting.md`, the cross-model model-tuning layer, and `team-roles.md`, the always-on director/lead/worker/reviewer contract; the dir serves both config dirs via the `claude/rules` symlink). Language dirs left in `claude/rules/` by the retired ECC rules vendoring are NOT inert -- they auto-load per the semantics above -- so delete any that remain (`claude/rules/.gitignore` keeps them uncommitted).
- `claude/operating-principles.md` -> `~/.claude*/` (both config dirs). `claude/global-instructions.md` `@import`s it into every session as standing, model-agnostic engineering discipline. Linked by `link_claude_config_dir`. (Per-model audit deep-dives `Fable5.md`/`Opus4.md`, if present locally, are gitignored and never committed — they hold private session content.)
- `codex/` -> `~/.codex/` (AGENTS.md, hooks)
- `claude/settings.json.tmpl` is seeded to `~/.claude/settings.json` and `~/.claude-work/settings.json` on first install, then reconciled on every `update`/link run (`reconcile_claude_settings_file` in `install/common/claude-links.sh`): template-owned keys (hooks, statusLine, permissions, env, model, promptSuggestionEnabled, tui) are reasserted, plugin-installer keys (`enabledPlugins`, `extraKnownMarketplaces`) are unioned with live state winning, retired plugins (`RETIRED_CLAUDE_PLUGINS_JSON`) are pinned off while still registered and dropped from `enabledPlugins` once gone, with their marketplaces and env keys swept, unknown keys preserved. A machine-local, owner-created `<config-dir>/settings.override.json` may set `model` for that config dir (model only; other keys are ignored with a warning; the reconcile never creates it), e.g. `printf '{"model":"opus"}\n' > ~/.claude-work/settings.override.json`. The personal config always disables Atlassian; work config retains its existing choice. The files stay machine-local (installers write to them) — never symlink them. Before the reconcile, `link_claude_config_dir` runs `sweep_retired_claude_plugins`. It removes any still-registered retired plugin: ECC through `claude plugin marketplace remove ecc`, and Superpowers through a user-scope CLI uninstall. Any records left over are pruned from `installed_plugins.json` with a `.bak-retired-*` backup. The sweep also removes the plugin's clone, cache and `temp_git_*` clones. It runs every CLI call from an empty temp cwd, so no project's settings file is touched. `update --ai` re-runs it strictly and exits non-zero after the Codex steps if it cannot finish.
- `bin/identity-setup` -> `~/bin/identity-setup` — interactive wizard writing `~/.gitconfig-work`, `~/.ssh/id_ed25519_work.pub`, `~/.ssh/config_local`
- `bin/identity-doctor` -> `~/bin/identity-doctor` — read-only chain verifier; also reachable as `git identity`
- `bin/op-env` -> `~/bin/op-env` -- headless agent credentials per project. Reads `op.env` (mode 600 at the main checkout root, or `$OP_ENV_FILE`) and `project.env` (`op://` references only; a worktree's own copy wins), resolves them with a bounded `op run --no-masking`, and prints `export` lines that `claude()`, `bin/zed-claude-agent` and herdr Claude pane prep (`herdr_dispatch._op_env_prep_line`, ready wait 50 s) eval. `GH_TOKEN` adds `GIT_CONFIG_SYSTEM=git/agent-https.gitconfig` (HTTPS rewrites that win git's equal-length rewrite ties because system scope is read first) and two `GIT_CONFIG_COUNT` entries that reset `credential.https://github.com.helper` at command scope and set the `GH_TOKEN` helper, so global and repo-local helpers never see the token (helpers set at other scopes or for other hosts are not reset). `project.env` names are an allow-list: an uppercase identifier ending in `_TOKEN`, `_KEY`, `_SECRET`, `_PASSWORD` or `_PAT`, or one listed in `op.env` as `OP_ENV_ALLOW=NAME1,NAME2`; the floor `PATH`, `HOME`, `SHELL`, `ENV`, `IFS`, `SHELLOPTS`, `BASHOPTS`, `BASH_*`, `PS0` to `PS4`, `PROMPT*`, `LD_*`, `DYLD_*`, `GIT_*`, `OP_*`, `CLAUDE_*` is refused even when listed, and `op run` starts with every listed name unset and execs `env -0`, so only values op set are printed. `OP_SIGNING_KEY` adds `GIT_CONFIG_COUNT` entries that point `gpg.ssh.program` at `bin/op-env-sign` (used by absolute path, not linked), which lazily loads the key into a plain ssh-agent at `~/.local/state/dotfiles/op-env-signing.sock` with a TTL, started under `env -i PATH` so it holds no session credential. `op-env status` feeds `identity-doctor`; `bin/dotfiles-tests` scrubs the git overrides. Codex launches are not wired: Codex shells drop exported variables. Tested by `bin/op-env.test.sh`; operator docs in the README "Agent Credentials (op-env)" section, which holds the diagram.
- `bin/setup-op` -> `~/bin/setup-op` -- writes `project.env` from a template (listed in `.git/info/exclude`) and `op.env` (umask 077, a `mktemp` temp file in the root, then rename); `--rotate` replaces only the token, `--signing-key op://VAULT/ITEM` records the key reference and its public key.
- `claude/hooks/account_guard.py` — SessionStart hook that warns when personal work uses a work account; work repositories allow either account (registered in `settings.json.tmpl`; drift-checked by `claude-hooks.test.sh`)
- `claude/hooks/handoff_notice.py` -- SessionStart hook (`startup|clear|compact|resume`) that lists the saved handoff records for the session's repository and account with task ID, role, and first brief line, then hints `/kickoff <task>`. Retired tasks (`handoff retire`) are skipped, and a `done:` record older than 72 hours is replaced by one hidden-count line. Advisory: silent and exit 0 on any failure; never selects or attaches a record and does not know whether a task is already being worked (registered in `settings.json.tmpl`; tested by `handoff-notice.test.sh`).
- `claude/hooks/herdr_pending_notice.py` -- SessionStart hook (`startup|clear|compact|resume`) that runs the core's read-only `pending` verb for the session's repository and account and, when tasks await a director action and `owner.json` holds no live lease (heartbeat within 900 s, the wake guard's rule), adds one line: `[INFO] herdr: N tasks await the director (oldest <task> since <date>); run director in a herdr pane`. `pending` evaluates the check-in rules without a herdr poll (poll-dependent rules skipped) and writes nothing, including worktree indexes (`--no-optional-locks`). Advisory: silent and exit 0 on any failure; never starts or wakes a director (registered in `settings.json.tmpl`; tested by `herdr-pending-notice.test.sh`).
- `claude/hooks/director_rollover.py` -- SessionStart hook for a herdr director (`HERDR_ENV=1`, payload `agent_type` director, a messaging socket). On `startup` with `HERDR_ROLLOVER_TOKEN` set it runs the core's `adopt-rollover`, which takes a lease the old director handed to this pane through `rollover-pending.json`; on `clear|compact` it runs `resume-owner`, which re-claims the lease this Claude process already holds (same pid, ancestry, start identity). It injects the `[INFO] herdr director rollover` block (fence, carried notes, wake-watch liveness, next step) or a `[WARNING]` block. On every source it then appends the core's `decisions` block (live owner decisions from `decisions.jsonl`, `--no-carry` after an adopt). After a successful lease block (exit 0 only) it appends a static host-sleep note that points the director at the SKILL.md section 6a step 0 host-sleep re-gate rule. An unarmed pane gets the unarmed warning first. Silent for any other session; always exits 0. The fenced `rollover` verb splits a new pane, writes the marker, starts `director` there, and waits for the ack; the old director then closes its own pane (registered in `settings.json.tmpl` on `startup|resume|clear|compact`; tested by `director-rollover.test.sh`).
- `claude/hooks/director_delegate_hint.py` -- PostToolUse hook (matcher `*`) for a herdr director (`HERDR_ENV=1`, payload `agent_type` director, no `agent_id`, session owning a repo lease). It counts the director's own work-shaped tool calls since its last dispatch (`Agent`/`Task`/`Workflow`, or an adapter `launch|advance|accept-review|dispatch-gate|reprompt`, or core `run-mech|run-think`) in `<rd>/delegate-hint.json`. Core, adapter, `gh` and `herdr` calls and the director's own reads are free. Every 20 work calls it adds one `[INFO] herdr: ... hand this slice to a worker ... or an Explore/general-purpose subagent` line. Advisory: silent and exit 0 on any failure; Claude only (registered in `settings.json.tmpl`; tested by `director-delegate-hint.test.sh`).
- `claude/hooks/herdr_worktree_guard.py` — PreToolUse Bash hook that denies `herdr worktree create` without `--cwd` (a bare create anchors to the herdr server's current repo, not yours); `worktree open` is not guarded (registered in `settings.json.tmpl`; drift-checked by `claude-hooks.test.sh`)
- `claude/hooks/herdr_stop_gate.py` -- Stop hook for indexed implementation/review workers. Native completion must match the selected account, repository, and current launch/phase/commit; legacy completion keeps its launch-time check. A native attempt owes the record of its own row's phase (plan/implement: done, review: review), not the workspace index role's, and a ship row is never asked for a record. A fresh stop receives one emit-record nudge, and an already-active stop cycle releases without another refusal. A bounded-runner child (`HERDR_BOUNDED_CHILD=1`) is always allowed. A native attempt is gated only in its own pane: a session whose `HERDR_PANE_ID` is missing or differs from the dispatched `pane_id` (or, with no current row of the index role, the latest native row's pane) is released silently (co-review helper sessions), and `emit-done`/`emit-review` exit 3 from such a pane inside herdr. A worker a task lead launched (the one claimed binding whose final row names the pane) is gated the same way against the lead subtree (`leads/<binding>/tasks`), with `--binding` on the emitter line. Reads state only and leaves other sessions untouched (registered in `settings.json.tmpl`; tested by `herdr-stop-gate.test.sh`).
- `claude/hooks/orch_edit_guard.py` -- PreToolUse guard for the orchestrator's Edit, Write, and Bash calls. It checks the shared owner binding, selected account, and live fence before refusing writes to tracked or unignored files in any git work tree, including git work-tree writes (`commit`, `merge`, `cherry-pick`, `reset` and similar); a fenced, short-lived `allow-edit` marker permits only a human-approved small edit and is budget-audited in `tasks/orch-edits.jsonl` (registered in `settings.json.tmpl`; tested by `orch-edit-guard.test.sh`).
- `claude/hooks/pr_post_guard.py` -- herdr-only (`HERDR_ENV=1`) posting gate and second layer behind the gh shim. A `draft -- gh <args>` CLI records a gated call as a pending draft with the text it shows (one file per draft, state in its name). PostToolUse `AskUserQuestion` turns the owner's answer to a post option (`... (draft <hash>)`, or the legacy `Post draft <hash>`) into an approved draft when the draft's text was in that question, and turns a skip option (`... (skip draft <hash>)`, or `Skip draft <hash>`) into a dismissed one. The option verb must name the event the draft's argv carries (`review_event`): `Approve` for a pinned APPROVE reviews-API draft, `Request changes` for REQUEST_CHANGES, `Post` for everything else; registration refuses an approving or request-changes call that is not a POST to `pulls/<n>/reviews` with a 40-hex `commit_id`. One question may name several drafts only when their recorded texts are equal; the chosen post option dismisses the others. Typed text never approves. The single PreToolUse `AskUserQuestion` group lists `opaque_label_hint.py` (warn-only) then this hook, which refuses, with the fix, a prompt whose post option names an unregistered draft or one whose text is not in the question, or whose draft label is ambiguous (no verb, both verbs, a lead word other than `Post`, `Approve` or `Request changes` before `post draft`, or two hashes), before the owner answers (read-only; approved drafts pass so `Skip` can withdraw them). UserPromptSubmit writes `pid-<claude pid>.sid` so the shim finds the drafts after `/clear`, removes legacy files and prunes. PreToolUse Bash denies a call holding more review/reply calls than approved drafts; denies outright a path-qualified `gh`, a login shell the PATH anchor misses, and `gh` text sent to another herdr pane; and denies every `gh` mention when `gh` on the session PATH is not the shim (registered in `settings.json.tmpl`; tested by `pr-post-guard.test.sh`).
- `claude/hooks/gh_post_shim.py` and `bin/herdr-shims/gh` -- the exec-time half of the posting gate. Herdr agent launches put `bin/herdr-shims` first on PATH: the `claude()`/`codex()` wrappers, the herdr dispatcher, and `agent_runtime.arm_gh_shim` for headless children. The shim classifies the final argv with `pr_post_guard`, reads the target PR's author once per session (`<sid>.authors.json`), refuses, in every repository and before any draft is spent, an approving or request-changes review whose `commit_id` is not the PR's live head (read at exec), lets own-PR maintenance and green evidence through with a `gh shim: [INFO]` line, spends one approved draft (`<sid>.draft-<hash>.approved` -> `.spent`) for text aimed at a person,, and execs the real `gh` found later on PATH; `DOTFILES_REAL_GH` is a test seam that picks that binary. `bin/herdr-shims/path.sh` is the PATH anchor: the end of `zsh/.zprofile` and `zsh/.zshrc` sources it, bash reads it through `BASH_ENV` (Codex receives it as `-c shell_environment_policy.set.BASH_ENV`), and it moves the shim dir back in front after a login shell re-derives PATH. A pre-set `BASH_ENV` is left alone. Tested by `gh-shim.test.sh`.
- `claude/hooks/scratch_policy.py` -- PermissionRequest hook (Bash matcher) that answers a residual permission prompt with `allow` only when every segment is a plain `rm`/`rmdir` whose every target canonicalizes strictly under a throwaway root (the payload's `scratchpad_dir`, `$TMPDIR` or `/tmp` when it is unset, or a `tmp.*` mktemp entry directly under `/tmp`); wrappers, pipes, redirections, `..`, symlink escapes, globs through symlinks, `.git` targets, and checkouts at or under a shared temp root all yield no decision so the prompt proceeds; it never denies (`rm_guard.py` runs first as PreToolUse and its block suppresses the event); allows are audited to `tasks/<task_id>.policy.jsonl` (or, for a worker a task lead launched, the lead subtree `leads/<binding>/tasks/`) only when the selected account and worker binding resolve safely; ambiguous or stale bindings skip the audit without changing the permission decision (registered in `settings.json.tmpl`; tested by `scratch-policy.test.sh`; live registration drift-checked by `claude-hooks.test.sh`)
- `claude/hooks/git_remote_guard.py` -- PreToolUse hook (matcher `Bash|Edit|Write`) that, only when `HERDR_ENV=1`, denies git-metadata mutations aimed at a real checkout: `git remote remove|rm|set-url|rename|prune` and `git config` writes to `remote.*`, `core.*`, or a branch's `remote`/`merge`/`pushremote` (or `--global`/`--system`, `--git-dir`/`--work-tree`, `--edit`, an unresolvable key, or an unrecognized option) unless every possible working directory is a fixture repository under `$TMPDIR` or `/tmp` (never under HOME) whose git common dir is also under a temp root; `git branch -d|-D` and `git worktree remove` of another orchestrated task's branch or worktree (records under the herdr state root with status other than merged/failed/abandoned, read only; the session's own task is exempt); and Write/Edit, redirections, tee, cp, mv, truncate, or sed -i into `.git/config` or `.git/info/exclude` outside a temp root. Working directories are tracked as a set (a `cd` may be skipped, undone by a subshell, or fabricated by a quoted operator), so the incident shape `( cd "$repo" && git remote remove origin )` denies while `git -C <fixture> ...` allows. `DOTFILES_ALLOW_GIT_META=1` as a leading env assignment overrides one segment after explicit user confirmation (registered in `settings.json.tmpl`; tested by `git-remote-guard.test.sh`; live registration drift-checked by `claude-hooks.test.sh`)
- `claude/hooks/planning_artifact_guard.py` -- PreToolUse hook (matcher `Bash`, every session) that refuses `git add`/`git stage` of a pathspec under `docs/specs/`, `docs/plans/`, `docs/superpowers/`, `.planning/`, or `claude/contracts/` (top-level-relative, case-folded), `git add -A|-u|.|<dir>` when `git status` would stage a non-deletion entry there (with `-f`, ignored entries too), and `git commit` whose index (with `-a`/`-i` the worktree, with `--amend` HEAD's own change set, with `-o`/pathspecs those paths) records one. Working directories are tracked as a set like `git_remote_guard.py`; a non-literal `cd`, or a `pushd` without a literal directory operand, falls back to the payload cwd, while `pushd <dir>` tracks like `cd`; a pathspec holding a shell variable or command substitution cannot be resolved or trusted as a literal prefix, so it forces a whole-tree scan instead of skipping. A repository under `$TMPDIR`/`/tmp` and not under HOME is exempt only when its resolved `--git-common-dir` is also under a temp root (so a linked worktree of a real HOME repo checked out under /tmp is not exempt); `DOTFILES_ALLOW_PLAN_ARTIFACTS=1` as a leading env assignment overrides one segment. Git calls share a 10 s budget and fail open. The same file is linked for Codex (registered in `settings.json.tmpl` and `install/common/codex-links.sh`; tested by `planning-artifact-guard.test.sh`; live registration drift-checked by `claude-hooks.test.sh`)
- `claude/hooks/signer_guard.py` -- PreToolUse hook (matcher `Bash`, every session) that fails fast when 1Password is locked. It reads the last complete `Lock state changed: Locked|Unlocked` line from 1Password's own log (`1Password_rCURRENT.log`, then up to 3 rotated files by descending numeric suffix; unreadable files are skipped, a missing log or line means unknown and allows). Only when that state is `Locked`, it denies (exit 2) a `git commit|merge|rebase|cherry-pick|revert|am|pull` segment whose effective repo config signs with `op-ssh-sign` (`gpg.format ssh`, `commit.gpgsign` true; the command's own `-c` and `--no-gpg-sign` are ignored so they cannot dodge it; `--ff-only` merge/pull are exempt), and a `git push` with any SSH destination URL. It never runs ssh, ssh-add, ssh-keygen, op or the signer, so it cannot raise a prompt; its only subprocesses are `git config`, `git remote get-url`, `git symbolic-ref` under one 10 s budget, and it fails open. The refusal tells a herdr worker to emit `paused` / `blocked_on_human`. `DOTFILES_ALLOW_LOCKED_SIGNER=1` as a leading env assignment overrides one segment after explicit user confirmation. The same file is linked for Codex (registered in `settings.json.tmpl` and `install/common/codex-links.sh`; tested by `signer-guard.test.sh`; live registration drift-checked by `claude-hooks.test.sh`).

Installed via the common Brewfile; usage is opt-in per machine (`herdr` to
start/attach, `herdr server stop` to stop). Never run
`herdr integration install claude` (or `codex`) on a dotfiles-managed machine:

this repo and adds hook entries to `settings.json` that
`reconcile_claude_settings_file` wipes on the next `update` (hooks are a
template-owned key) and the settings drift check flags meanwhile. Herdr's
agent-state detection works without the integration (screen manifest); if the
integration is ever wanted, it needs the installer-owned pattern (post-reconcile
idempotent install step) plus a gitignore entry for the generated script.

Generated detection override: herdr has no Claude rule for background shells,
so `install/common/herdr_manifest.py` writes
`~/.config/herdr/agent-detection/claude.toml` (machine state, never tracked)
as herdr's cached remote `claude.toml` (`$XDG_STATE_HOME/herdr/agent-detection/remote/`)
plus the one rule in `herdr/agent-detection/claude-rules.toml`: a footer
`N shell(s)` counter means `working`. A local override replaces herdr's whole
manifest, so the file is regenerated by the full install (`install/common/link.sh`)
and `update --ai` (`install/common/ai-update.sh`), then
`herdr server reload-agent-manifests` runs. Line 1 is a marker: a file without
it is user-authored and left alone (delete the marker line to keep a hand edit).
Residual: herdr remote manifest updates, and a newer bundled manifest after a herdr binary upgrade, are shadowed until the next regeneration (`update`).
Rollback: revert the commit, wait until `pgrep -f herdr_manifest.py` prints
nothing, delete the override, run `herdr server reload-agent-manifests`.

**Claude Code mods:**

`claude/plugins/herdr-fleet` is a Claude Code mod (hooks module plus
`$.state` contract) that draws the director's fleet pane. The tasks tab
groups active tasks by who acts next (Your call, Needs director, Waiting on

number, title, what it waits on and the time since the latest activity; a
status icon (bell, compass, eyes, robot) leads each group header, and a PR with
a human change request sits under Your call. The PR tab has one row per open
PR. A stack cell follows the `#<pr>` cell on the PRs tab, and on task rows
when the title keeps its minimum width, once any listed PR is stacked. A PR
whose base (`baseRefName`) is the head branch of exactly one other listed
same-repository PR (`isCrossRepository` false) sits above it. The cell reads
`2/3 #301` (position, height, root PR), `2/3 blocks 1` for the lowest PR below
the top with failing CI or changes requested (its row draws yellow on the PRs
tab), and `3/3 blocked by #302` for every PR above that blocker. A base with no
listed PR makes the lowest listed PR the stack root, and a lone PR shows no
cell. The Queue tab (hotkey 4) lists the todos in `<state>/<slug>/queue.json`,
which the director writes with the core's fenced `set-queue` verb (at most 10
pending todo ids); a todo that any task record names, or that has no pending
file, is hidden. Cells link out through the terminal's hyperlinks: a task title

the account directory that `workflow_context.py account-scope` names, or under
`TODOS_DASHBOARD_DIR`, + `#todo-<id>`), a `#<pr>` cell to the `url` that `gh
pr list` returns (or the record's `pr_url`), and a Jira key to
`$JIRA_URL/browse/<KEY>` when `JIRA_URL` is set in the director's environment. The grouping joins the record with GitHub
review state from `gh pr list --author @me` (`reviewDecision` and `reviews`;
an empty decision means no review rule applies) and with the review verdict
sidecar `tasks/<id>.review.json`. `director()` (`zsh/claude-account.zsh`) loads it
with `--plugin-dir` when the directory exists; it is never installed from a
marketplace and has no `enabledPlugins` entry. `claude/plugins/` is not linked
